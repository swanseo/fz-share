1. 지금 넘기는 범위

기획자가 하는 판단은 전부 고르기입니다. 그리는 일도, 포토샵도 없습니다.

2. 왜 여기서 끊는가

숨기지 않고 적습니다. 애니메이션이 아직 안 되는 이유는 두 가지입니다.

2-1. 부위는 맞대는 것이 아니라 겹쳐야 합니다

탑다운 캐릭터를 부위로 나눌 때 보이는 대로만 오리면 애니메이션에서 구멍이 뚫립니다. 팔이 돌아가는 순간 어깨 안쪽의 가려져 있던 자리가 드러나는데, 그 부분은 애초에 그려져 있지 않기 때문입니다.

지금까지 결과가 계속 어긋난 원인이 여기 있었습니다. 원작 그림의 최종 화면은 이미 서로를 가린 뒤의 모습이라, 그것을 기준으로 오리면 가려져 있던 여유분이 통째로 빠집니다. 필요한 것은 결과 상태가 아니라 “움직였을 때 어디까지 드러나는가”이고, 이 값은 리그의 회전 범위에서 계산해야 합니다.

실측 — 소매의 77%가 피부 팔 위에 얹히고, 피부 팔의 47%가 소매에 덮입니다.

2-2. 걷기와 공격은 성질이 다릅니다

걷기공격
캐릭터마다 다른가거의 같다성향이 곧 동작이다
자동화목표 — 공통 샘플 1개를 돌려쓴다시스템화하면 전부 평균값이 된다
지금 하는 일원작 참조 + 새로 디벨롭그래픽이 포토샵에서 직접
자동화 경계샘플이 맞으면 그때 기계에PSD → 스프라이트 굽는 구간부터

둔기·사격·돌진을 한 리그로 뽑으면 셋 다 어정쩡해집니다. 그래서 공격 모션은 동작 설계를 사람이 하고, 그 뒤 반복 노동만 자동화하는 쪽으로 정했습니다.

3. 이렇게 씁니다

기획자는 명령어를 외우지 않습니다. Claude에게 말로 시키면 됩니다.

말로 시키기

“LA 도심 갱단 좀비 6종 컨셉 뽑아 줘. 이름은 la-gang.”

Claude가 도구를 돌리고, 그림이 필요한 순간 이미지 AI를 불러 채워 넣고, 미리보기까지 열어 둡니다.

골라서 답하기

“3번 시트가 좋아. 5번 유닛으로 탑다운 뽑아 줘. 2번으로 확정.”

판단은 전부 고르기입니다. 확정하면 그래픽에게 넘길 것이 자동으로 정리됩니다.

⚠️ 도구는 고르지 않습니다. 사람이 고릅니다. 카메라 이탈은 기계가 잡지 못합니다 — 종횡비로 거르려 했으나 정면 전신 후보가 정상 후보보다 좋은 점수를 냈습니다. 그래서 여러 장 뽑아 눈으로 고르는 것이 이 도구의 전제입니다.

4. 준비물은 넷입니다

기획자 PC에서 한 번만 하면 됩니다.

  1. 파이썬 3.10 이상 — 설치 화면의 Add python.exe to PATH 체크가 중요합니다.
  2. 저장소 받기 — GitHub 초대는 이미 되어 있습니다. 받은 뒤 설치 스크립트 한 줄이면 가상환경·패키지·점검이 끝납니다.
  3. Claude Code — 데스크톱 앱 또는 터미널. 저장소 폴더에서 열면 프로젝트 규칙을 자동으로 읽습니다.
  4. 이미지 생성 MCP 연결 — Higgsfield 등. 각자 계정으로 한 번 로그인해야 하며, 이건 대신 해 드릴 수 없는 부분입니다.

5. 실제로 돌려 봤습니다 ★

그림을 미리 넣어 두고 돌리던 검증을 넘어, 이미지 AI를 실제로 호출해 전 구간이 이어지는 것을 확인했습니다.

측정값판정
채도 중앙값55.5기준 53.0 대비 +2.5 — 후보 중 원작에 가장 가까움
32px 실루엣 채움66.9%하한 40% 통과
카메라—정수리 · 어깨 덩어리 · 앞으로 뻗은 두 팔 · 다리 없음
비용 / 시간2 크레딧약 40초

참고 — 같은 유닛의 기존 후보 4장은 채도가 기준보다 +32 이상으로 떠 있었습니다. 이번 것이 가장 원작에 가깝습니다.

이 과정에서 제약을 하나 발견했습니다. 이미지 AI에 참조 이미지를 URL로 넘길 수 없습니다. 업로드 URL 발급 → 바이트 전송 → 확인, 3단계를 거쳐야 합니다.

기획자가 손으로 할 수 있는 일이 아니라서 스크립트가 흡수하도록 만들었습니다. 기획자는 이 단계를 볼 일이 없습니다.

6. 계정과 비용

위 검증은 그래픽 계정에서 한 것입니다. 계정이 다르면 달라지는 부분을 분명히 적습니다.
